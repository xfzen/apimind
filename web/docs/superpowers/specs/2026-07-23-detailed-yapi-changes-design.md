# ApiMind Web 详细改造文档设计

## 目标

在不扩大根 README 篇幅、也不改变 `MODIFICATIONS.md` 来源与许可摘要职责的前提下，新增一份默认中文的详细改造文档，帮助读者理解 ApiMind Web 相对 YApi Web 的主要变化、实际价值和兼容边界。

## 文档位置

- 新增：`docs/changes-from-yapi.md`
- 中文根 README 的“主要修改与改进”章节链接该文档。
- 中文文档索引的“当前开发与验证”章节链接该文档。
- `MODIFICATIONS.md` 和英文 README 保持现有职责与内容，不新增英文详细文档。

## 内容结构

文档沿用根 README 第一版的八个改造维度：

1. 应用架构；
2. 前端技术栈；
3. 文档体验；
4. 项目复用；
5. 导入导出与插件；
6. 安全；
7. 构建与部署；
8. 工程质量。

每个维度统一说明：

- YApi 基线；
- ApiMind Web 的具体改造；
- 对 API 研发工作的影响；
- 兼容性或使用注意事项；
- 当前源码、配置或验证脚本依据。

每个维度使用纵向表格呈现以上五类信息，避免一张超宽总表降低 GitHub 和窄屏阅读体验。文档另设“范围与说明”“保留的兼容能力”“明确不包含的内容”“相关文档”表格，明确它描述的是当前代码快照，不代替源码、Server 契约、迁移记录或许可证文件。

## 内容边界

- 不扫描或复述 Git 历史；
- 不宣称尚未由当前代码证明的功能；
- 不把 PC App、Server 内部实现或未来 PostgreSQL 规划写成 Web 当前能力；
- 不重复许可证正文；
- 不把历史 YApi 文档当作当前行为的权威来源。

## 验证

- 运行公开文档链接和必备章节校验；
- 运行仓库边界与容器配置相关测试；
- 运行 `git diff --check`；
- 人工确认新增文档中的实现依据路径均存在。
